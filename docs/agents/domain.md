# Domain docs

This repository uses one context.

## Read before exploration

1. Read `CONTEXT-MAP.md` at the active alignment root.
2. Read `CONTEXT.md` when it exists.
3. Read `docs/adr/index.md` and ADRs that affect the current area.

If a domain document does not exist, continue without it. Use the `domain-modeling` skill to record terms and decisions when they are resolved.

## Document layout

Keep the glossary and domain rules in `CONTEXT.md`. Keep architecture decisions under `docs/adr/`. Keep stable entry points in `CONTEXT-MAP.md`.

Use the glossary's terms in ticket titles, code proposals, hypotheses, and tests. Update domain documents when a resolved decision changes a term or rule.
