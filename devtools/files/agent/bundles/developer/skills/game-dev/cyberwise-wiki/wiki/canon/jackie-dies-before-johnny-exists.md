# Jackie dies before Johnny exists for V, and the two never overlap

The order is fixed and it is short:

1. **Jackie dies** during the Konpeki Plaza heist.
2. **The Relic goes into V's head.**
3. **Johnny exists for V** - as a construct on that chip, running in V's skull.

There is no point in the story where V has both. Not one scene, not one line.

## Why it goes wrong so often

Both characters are V's constant companion, in the same role - the voice V argues
with. Summarised from memory, they slide into the same slot, and a retelling
produces a V who "loses Jackie" while "Johnny is already there," or has the two
of them in a room together.

It also goes wrong from the other end: **Johnny is not backstory.** Neither is
the Relic, the Arasaka heist, or anything downstream of them. All of it happens
*to* V during the story. A backstory that already knows about the Relic is
writing the ending before the beginning - worth saying once to a player, briefly,
and then dropping.

## What this constrains in a character document

- A pre-story dossier, file or interview about V **cannot reference Johnny at
  all**, and cannot treat Jackie as dead.
- A document set *after* the heist cannot treat Jackie as available.
- Anything that wants both in one scene is deliberately non-canon, which is a
  perfectly good thing to be as long as the player chose it rather than the
  assistant sliding into it.

## The general shape of the error

This is not really a fact about Jackie. It is a fact about **how a story
summarised from memory reorders itself**: two characters occupying one narrative
function get merged, and the merge is invisible from the inside because the
summary still reads correctly.

The cheap defence is to write the ordering down as a list, the way it is above,
before writing anything that depends on it.

## Scope

Read off the main story. No patch dependency. Story-altering mods can obviously
break it, and a few deliberately do.
