## Acceptance criteria
│
│
│
│
1. The project list displays a name and origin or stable identity for each project. Equal
│
│
repository names remain distinguishable.
│
│
2. Keyboard focus reaches the Projects breadcrumb. Enter activates it. A mouse click
│
│
activates the same control.
│
│
3. Selecting a project resolves its routes before record access. The selected project owns
│
│
tracker reads, Files reads, and action targets.
│
│
4. The header displays Shared or Repo from the selected alignment route. The indicator is
│
│
read-only.
│
│
5. Project selection does not change the active Pi session directory or system
│
│
instructions.
│
│
6. Returning to a project restores its navigation, selection, and scroll position. Each
│
│
workspace retains independent state.
│
│
7. Project changes dispose of old watchers and attach the correct new watchers. Old
│
│
project updates do not change the selected project view.
│
│
8. A project without a usable checkout retains readable context. Checkout-dependent
│
│
actions display a clear disabled reason.
