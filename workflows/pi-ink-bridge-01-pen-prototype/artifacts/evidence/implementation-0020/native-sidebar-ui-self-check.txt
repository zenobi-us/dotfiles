UUID NORMALIZATION FOLLOW-UP — 2026-11-03
Finding: the native UUID seam has no explicit canonical string contract. Activation should not rely on an unproven serialization shape.

pi-ink-bridge.qmd:10-11 exports root.document.id.toString() unchanged. PiInkToolbar.qml:34 compares state.documentUUID to that string with strict equality. Lines 138-142 treat any spelling difference as a current-document mismatch and republish. The display at line 377 uses the unchanged native string.

Recovered DocumentView.qml:277-284 also calls openDocument.id.toString() when passing ignoreIds to the native document drawer. Lines 2640-2642 compare document.id.toString() to retailSettings.defaultDocumentId. Neither call proves lowercase, absence of braces, or whether Document.id is QString versus QUuid. A native consumer can accept the same native spelling, and the retail settings value's serialization contract is not defined here. The inspected recovered QML contains no Document.id type declaration, UUID format flag, or explicit brace/case normalization. No recovered .qmltypes or header file was found in the supplied offline directory.

Conditional failure scenario: if native toString() produces a braced or uppercase UUID, and the service returns a lowercase brace-free UUID, publication can succeed while every GET /state fails the comparison at lines 138-142. QML clears state, republishes, and remains in Updating current document. Send/Confirm stay disabled because currentMatches never becomes true. This is a source-proven consequence of divergent spellings, not proof that the actual tablet currently emits either spelling.

Go-source qualification: the checked-out tablet/operations.go:15-18 validates uuidPattern and lines 20-32 retain the supplied string unchanged. tablet/state.go:19 accepts mixed case but no braces. tablet/main.go:174 returns c.current as documentUUID. A repository-wide Go-source search found no safeUUID helper. Thus the reported safeUUID canonicalization may belong to the pending revised source rather than this inspected checkout. Under this checkout, a braced UUID instead fails POST /current; case alone is retained, but could still differ from association keys. The parent-provided safeUUID behavior remains the premise for the divergent-spelling scenario above.

Recommendation: normalize the current-document string once at the native QMD seam, before publication, display and press capture. For already valid native UUIDs, lowercase plus removal of one matched outer brace pair preserves identity. Keep the no-document value as "". Do not remove arbitrary punctuation, change confirmationId, or replace immutable press captures with later state. Keep backend validation authoritative. A single seam conversion avoids masking an actual stale-document mismatch by weakening currentMatches.

The native serialization shape remains unproven. This follow-up qualifies the earlier no-actionable-defect verdict: the UUID seam requires an explicit canonicalization decision before activation.
