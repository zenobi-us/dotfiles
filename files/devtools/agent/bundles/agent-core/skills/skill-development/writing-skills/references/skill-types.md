# Skill Types

Classify the skill before writing it. Classification determines the core shape and the tests.

## Reference

Use for lookup material such as APIs, syntax, command options, compatibility notes, and facts.

Test retrieval and correct application.

## Workflow

Use for an ordered process with gates, decisions, and completion criteria.

Test whether the agent follows each step and stops only when the completion criteria are met.

## Style guide

Use for standards and conventions such as naming, formatting, tone, and structure.

Test representative examples and counter-examples.

## Persona

Use for a behaviour profile that sets interaction style, priorities, and boundaries.

Test behaviour under conflicting requests and pressure.

## Technique or pattern

Use for a repeatable method or mental model.

Test recognition, application, variation, and cases where the pattern does not apply.

## Multiple types

If a skill spans multiple types, ask whether the scope is intentional.

If the user wants one skill:

1. Choose one primary type.
2. State the primary type in the overview.
3. Use references for secondary material.
4. Test the complete skill with the primary type's method.

If the user wants separate skills:

1. Split by audience, lifecycle phase, problem type, or artifact type.
2. Give each skill one clear purpose.
3. Create one implementation plan per skill.
4. Test each skill separately.
